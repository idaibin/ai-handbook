# AI Engineering Handbook v0.1

这是一个以可复现产出为中心的个人 AI Engineering 学习手册，而不是课程收藏夹。中文为主；每项内容必须说清 **Input、Output 与证据状态**。

## 两个固定角色

| 资源 | 角色 | 使用方式 | 不承担的职责 |
| --- | --- | --- | --- |
| [Agent Learning Hub](https://github.com/datawhalechina/Agent-Learning-Hub) | 路线与门禁 | 决定先学什么、何时进入下一阶段 | 不能替代实现或实验记录 |
| [ai-agents-from-zero](https://github.com/didilili/ai-agents-from-zero) | Python 实验教材 | 每个概念至少做一个可运行、可复现的最小实验 | 不能单独证明生产可用 |

准确仓库地址以 [来源目录](sources/README.md) 中登记的用户提供链接为准。本轮已核对两个仓库的公开 README/目录；示例运行性、个人学习进度与项目适配性仍须分别验证。未验证条目不得作为学习完成或工程结论的依据。

## 工作闭环：Pull，而非堆积

采用 Pull 模式：由当前阶段的交付物和失败点拉取下一条最小来源，而不是预先把课程全部排期。

```text
交付物缺口 / 实验失败
        ↓ Pull
来源卡片 → 最小实验 → 证据 → 可复用 Skill / 知识蒸馏 → 阶段门禁
                                      ↑                         │
                                      └──── 下一阶段需求 ────────┘
```

1. 先定义本阶段 Output 与验收证据。
2. 只 Pull 能填补当前缺口的来源；同一概念优先选择一个主来源。
3. 实验通过后提炼为可复用步骤；不能复现则保留失败证据，不升级状态。

去重规则：按「要解决的问题 + 可验证产出」去重，而不是标题或公司名称。同一问题保留一个主来源，其他来源仅在提供不同证据、不同实现路径或纠正主来源时保留。

## 学习与应用状态

`learning_status` 记录个人学习与复用进度；来源到摘要的映射是否核对由 `source_verification` 单独记录。

| `learning_status` | 含义 | 可用于 |
| --- | --- | --- |
| `unverified` | 尚未形成可复核的阅读卡、复现或应用证据 | 待办，不可宣称学完 |
| `read` | 已阅读并有来源卡片 | 概念讨论 |
| `reproduced` | 最小实验可复现，有命令、环境和输出 | 阶段候选 |
| `applied` | 在真实任务中使用并有复盘 | 复用候选 |
| `distilled` | 已沉淀成可执行知识或 Skill，并回链证据 | 长期基线 |

详细地图见 [AI Engineering Map](maps/ai-engineering-map.md)，阶段门禁见[学习路径](roadmap/learning-path.md)。

## 目录

- `maps/`：能力地图、依赖关系与阶段门禁。
- `roadmap/`：以产出驱动的学习路径。
- `sources/`：来源目录和收录规则；十类公司课程只作为待验证输入。
- `templates/`：单个来源的证据卡模板。

## v0.1 边界

本版本定义工作法、门禁和来源台账；没有声明任何外部课程已完成，也没有把静态阅读等同于运行时或生产验证。
