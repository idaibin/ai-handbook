# 学习路径：产出驱动 v0.1

每阶段只在当前阶段 Output 达标后进入下一阶段。周期不是门槛；证据才是。

| 阶段 | Pull 条件 / Input | 必做 Output | 门禁证据 | 下一步 |
| --- | --- | --- | --- | --- |
| A. 定义 | 一个真实问题或微型场景 | 一页问题卡：用户、I/O、约束、失败条件 | 可被他人据此判断成功/失败 | Pull 最小 Python 实验 |
| B. 最小实验 | Hub 指向的能力缺口；教材中的对应章节 | 一个独立 Python 实验 | 锁定环境、运行命令、输入与输出 | Pull Agent 基元或检索实验 |
| C. 工作流 | B 已复现；出现多步骤/工具需求 | 一个有结构化 I/O 的工作流 | 正常、异常、边界各至少一个案例 | Pull 评估方法 |
| D. 可靠性 | C 的失败案例或不稳定输出 | 小型评估集与阈值 | 可重复报告成本、时延、正确性 | Pull 交付约束 |
| E. 应用 | D 达标且有明确使用场景 | 可演示的端到端交付物 | 权限、日志、失败处理、回滚边界 | Pull 蒸馏与复用 |
| F. 蒸馏 | E 有稳定、可复用步骤 | Skill 或知识条目 | 回链证据；第二次使用或标注未验证 | 回到新问题 |

## 每阶段最小包

```text
Input：数据 / 约束 / 版本
Output：代码或文档产物 / 可观察结果
Evidence：命令、日志、测试、截图或评估报告
Status：unverified | read | reproduced | applied | distilled
```

## 课程使用原则

十类公司课程在 `sources/catalog.yaml` 中均为 `unverified`：它们是候选 Pull 池，不表示已学习、已验证或适合当前阶段。进入某课程前，先写明它要填补哪一个阶段 Output 缺口；完成后用来源卡和实验/项目证据更新状态。
