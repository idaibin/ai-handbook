# AI Engineering Map

## 能力地图

| 层 | Input | Output | 最低证据 | 典型失败 |
| --- | --- | --- | --- | --- |
| 0. 问题定义 | 用户任务、约束、成功条件 | 可测验收标准与风险边界 | 需求卡 + 反例 | 目标只是“做个 Agent” |
| 1. Python 实验基础 | API/模型、最小提示词、固定数据 | 可运行单步实验 | 环境、命令、输出 | 不可复现、结果不可比较 |
| 2. Agent 基元 | 工具、状态、结构化 I/O | 工具调用、循环、错误处理实验 | 测试或运行记录 | 把提示词当控制流 |
| 3. 检索与知识 | 语料、切分、检索策略 | 可审计的带引用回答 | 样本、命中与失败案例 | 幻觉、引用错配 |
| 4. 评估与可靠性 | 测试集、断言、成本/时延预算 | 可重复评估报告 | 指标、阈值、回归结果 | 只展示单次成功 |
| 5. 交付与运维 | 接口、权限、观测、发布约束 | 可部署服务或工作流 | 端到端验证与回滚方案 | 静态检查代替运行验证 |
| 6. 复用与蒸馏 | 已验证实验/项目证据 | Skill、Runbook、知识条目 | 回链证据 + 二次使用 | 把未经验证内容固化 |

## 路线与教材的分工

Hub 是路线层：用能力依赖、门禁和风险决定 Pull 顺序。`ai-agents-from-zero` 是实验层：用 Python 把路线中的单一能力落成最小可运行实验。二者都不是最终证据；最终证据来自可复现运行、评估或真实应用。

## 阶段门禁

```text
问题定义
  └─ Gate 0：Input / Output / 失败条件写清
      └─ Python 最小实验
          └─ Gate 1：同环境可复跑，输出被保存
              └─ Agent / RAG / 工具编排
                  └─ Gate 2：有失败样本与评估阈值
                      └─ 交付
                          └─ Gate 3：端到端、观测、权限验证
                              └─ 蒸馏与复用
                                  └─ Gate 4：二次使用或明确未适用范围
```

任何 Gate 未满足时，回到上一个有证据的层级，按缺口 Pull 新来源或补实验；不以课程进度替代门禁。

## 与 Skills、Experiments、Knowledge Distillation 的关系

| 对象 | 进入条件 | 产物 | 退出条件 |
| --- | --- | --- | --- |
| Source | 当前 Output 有知识缺口 | 来源卡 | 已阅读、淘汰或转实验 |
| Experiment | 有可验证假设 | 代码、环境、命令、结果 | `reproduced` 或记录失败 |
| Skill | 任务步骤稳定且可复用 | `SKILL.md`/检查单 | 在新任务复用或降级 |
| Knowledge Distillation | 已验证证据可抽象 | 带来源和适用边界的知识条目 | 可回链、可检索、可更新 |

Skills 是执行接口，Experiments 是验证现场，Knowledge Distillation 是带证据的长期记忆；三者均需回链原始实验或来源卡。
