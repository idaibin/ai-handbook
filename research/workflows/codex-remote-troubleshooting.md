# Codex Remote：一次加载失败的排查经验

记录日期：2026-10-30。本文整理一次 Android 手机连接桌面 ChatGPT 的实际排障，供同类问题定位时参考。该次配对和消息读取最终恢复，原始加载失败的具体根因仍未证实；短时验收不代表长期稳定性，也不保证其他版本可复现。

## 观察与结论的边界

当次环境为 Android 17、ChatGPT Android 1.2026.293 (19)，桌面 ChatGPT 26.1027.30824，桌面内置 CLI 0.166.0-alpha.5.1。这些是历史环境记录，不是当前版本建议或兼容性矩阵。

| 观察 | 可以支持的结论 | 仍不能证明 |
| --- | --- | --- |
| 出现 401 / expired，但属于 Local Work 执行通道，随后自行恢复 | 该通道发生过短暂认证异常 | 手机 Remote 因凭证过期而失败 |
| 手机切换 Remote 开关时主线程出现 ConcurrentModificationException；新进程存活期间仍能复现消息读取失败 | 存在真实崩溃，也存在不依赖该次崩溃的读取失败 | 修好该崩溃就能消除全部加载失败 |
| 项目列表或顶部“已连接”出现，聊天正文仍读取失败 | 连接状态与内容读取需要分别验收 | Remote 已恢复可用 |
| 其他功能正常，Remote 仍失败 | 不同功能链路可能呈现不同结果 | 网络一定正常或一定是网络问题 |
| 授权回跳已进入应用，扫码和手动配对仍失败过 | 回跳到应用不等于配对完成 | 已定位回跳后的具体错误 |

## 恢复经过

在核对桌面内置 CLI 当版协议后，使用独立只读进程查询当前电脑环境的授权设备，返回为空。没有发现可删除的旧手机记录。

随后以临时 Remote 进程启用当版支持的 ephemeral 模式并生成手动配对码，核对返回的环境和安装标识与桌面对应，确认持久设置未变后退出临时进程。新码尚未提交，手机已转为 Remote 开启；随后授权设备清单出现对应手机，实际聊天历史与最新内容读取成功。

验收依据包括设备授权记录、实际聊天内容、两次短时采样和真实恢复录屏。它们证明该次有界恢复，不能证明某个协议调用造成恢复。授权注册异步完成等解释也没有被排除。

清缓存、重启、更新桌面和手机同版本重装均未单独带来已验证的稳定恢复。退出 Beta 后曾因商店状态传播而无法安装，之后按用户要求重装 Beta；未完成正式版对照。独立 CLI 从 0.164.0 升至 0.165.0 发生在恢复之后，不能作为恢复原因。

## 下次如何缩短排查

1. **固定目标。** 绑定真机、应用版本、账号、工作空间和电脑环境。把“未配对”“项目失败”“正文失败”“连接关闭”分开记录，先保存一次真实失败证据。
2. **追踪同一链路。** 固定复现时间，按 Remote 目标、连接标识和请求方法关联两端日志。其他执行通道的认证异常不能替代目标链路证据。
3. **查询实际授权状态。** 在授权和受支持接口范围内，核对设备清单、配对有效期和请求结果。独立进程显示 disabled，只描述该进程，不能据此判断桌面原进程状态。
4. **先确认工具身份。** 区分桌面内置 CLI 与包管理器安装的独立 CLI；核对路径、版本和当版 schema 后再执行语义操作。权限或协议不明时停止对应动作，不绕过 UI 限制，不猜 RPC 参数。
5. **限制实验影响。** 若当版明确支持临时模式，仍需核对环境和安装身份、持久配置前后差异，并结束自己创建的进程。本案例不提供可直接套用的协议修复脚本。
6. **验收实际使用结果。** 同时检查授权设备、项目列表、现有聊天正文及短时重连表现，保留真实恢复录屏；只看到握手或“已连接”不能收尾。

每轮测试应回答一个可证伪的问题。新证据不支持原假设时，缩小结论并改变检查方向，避免反复重置和仅重复描述现象。

## Beta 与 CLI 维护经验

切换 Beta 前，先核对账号侧测试资格、商店安装入口和可回装渠道。此次账号退出成功与商店状态曾不同步；缺少可安装渠道时，应暂停卸载。没有正式版对照结果时，不宣称正式版更兼容。

桌面协议排障先核对配套内置 CLI；独立 CLI 用其已登记包管理器维护，仅更新明确指定的目标，并核验升级后的路径、包来源和版本。本案例没有建立独立 CLI 版本与 Remote 故障的因果关系。
